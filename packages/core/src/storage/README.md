# Research storage

`ResearchStore` accepts a SQL client implementing `ResearchClient` and a trusted workspace ID. Existing `@libsql/client` clients satisfy that interface. Authentication must resolve that ID before calling the store; never take it from tool arguments. Application tables use the `app_` prefix and do not migrate Mastra tables. Initialization is explicit and idempotent.

Use a local `file:` database from **one application process**. Native writes are serialized in that process across store/client instances, and queued writes expire after five seconds before starting. The installed native libSQL driver can retain a busy prepared statement after competing file writers, causing later commits to fail. Sharing a writable file across application processes is unsupported. Split Docker deployments use remote libSQL, where the server serializes write transactions. No process-local lock gates remote clients, and transaction failures are surfaced rather than replaying an uncertain commit.

Cloudflare deployments use `createDurableResearchStore(storage, workspaceId)` with the owning Durable Object’s SQLite storage. Its injected transaction runner wraps each complete research mutation in `storage.transaction()`, including dependent reads, reservations, and usage settlement. Cursor rows are consumed synchronously before any await, and `changes()` supplies logical affected-row counts rather than index-write billing counts. Closing a client never deletes Durable Object storage. The private research RPC accepts only `RESEARCH_METHODS`; its workspace comes from trusted Worker configuration, not the request body.

Attempt IDs never change within a claim. Usage evidence is append-only and versioned per workspace/attempt. Initial evidence has revision 1, legacy reconciliation has revision 2, and further corrections append monotonically increasing revisions. The trusted `correctUsage` method corrects accounting without changing execution status. Settlement callbacks receive the revision as their optional fourth argument; consumers must ignore older revisions, deduplicate identical versions, and reject conflicting evidence for the same version. Mutable attempt balances project reported charges and retained reservations. Provider token counts and charges stay null when absent. A known charge releases its estimate reservation; uncertain or missing charges retain it. A pre-dispatch expired lease releases its reservation and returns to pending; a dispatched expired lease becomes `unknown_outcome` and cannot be reclaimed.

Retrieval IDs must be a stable key derived from the run, prompt, repetition, and retrieval options. Retrieval ownership is compare-and-set, bundle contents are immutable after success, and failed or uncertain retrievals cannot be claimed again. Retrieval charges use a distinct attempt key and are counted once per bundle. Failed retrievals retain their estimate when actual charges are missing; absence does not prove the request was unbilled. A completed bundle preserved through a failure fallback retains its raw evidence and known charge while keeping its failure status.

Missing model costs remain in a separate durable reconciliation queue after settlement ACK. Repair claims use leases and exponential backoff, and provider `reconcileUsage` hooks may read metadata only. Missing identifiers or absent evidence remain unresolved with retained reservations. Settlements deliver the oldest unacknowledged revision of each attempt; failed deliveries are deferred independently so other attempts progress. Explicit runtime repair processes bounded batches; new executions do not wait for unrelated billing repairs.
